# Vuxo 0.0.4

Account unico tra provider e super admin. / One account across providers and super admin.

## Player-visible changes / Per i giocatori

- **IT:** Se accedi con Google e poi con Microsoft (o viceversa) usando la stessa e-mail **verificata**, entri nello stesso account e nello stesso personaggio: non ne viene più creato uno nuovo. Il nome visualizzato resta quello del primo accesso.
- **EN:** Signing in with Google and then Microsoft (or the other way round) using the same **verified** e-mail now opens the same account and character; no new one is created. The display name stays the one from the first sign-in.

## Backend / realtime

- Collegamento per e-mail verificata in `SocialAuthenticationService`: se la coppia provider/subject è nuova ma l'e-mail verificata appartiene a un utente esistente (confronto case-insensitive, utente più vecchio in caso di duplicati storici), viene aggiunta una nuova `external_identities` allo stesso `vuxo_users`. Nessuna migrazione di schema.
- Fiducia nell'e-mail: Google solo con `email_verified=true`; Microsoft solo per account personali (tenant `consumers`). E-mail non verificate non collegano account e non vengono salvate.
- Super admin: `Auth:SuperAdminEmails` (env `VUXO_SUPER_ADMIN`, lista separata da virgole). Il JWT riceve il ruolo `Administrator` solo se il login corrente ha un'e-mail **verificata** presente nell'elenco; il confronto è case-insensitive e avviene lato server a ogni login.
- Audit `auth.social.login_succeeded`: rule version `social-auth-v2`, payload con `linkedByEmail`.

## Infrastructure / Infrastruttura

- `docker/compose.prod.yml` inoltra `VUXO_SUPER_ADMIN` a `Auth__SuperAdminEmails`.

## Tests / quality

- xUnit: collegamento cross-provider, e-mail non verificata, criteri super admin (parametrizzati) e riuso identità nei test API/Application.

## Known limitations / Limiti noti

- Account già duplicati prima di 0.0.4 (stessa e-mail, utenti diversi) non vengono uniti automaticamente: il collegamento usa l'utente più vecchio.
- Il ruolo admin dura quanto il JWT (default 480 minuti); rimuovere un'e-mail dall'elenco ha effetto al login successivo.
